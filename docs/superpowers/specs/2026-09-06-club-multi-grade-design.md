# 社团多年级报名设计

日期：2026-09-06  
状态：已确认，待编写实现计划

## 目标

将社团的可报名年级从单选改为多选，使一个社团可以同时面向初一、初二、初三中的多个年级报名，同时保持学生年级单选、现有报名记录和公共报名流程兼容。

## 已确认规则

- 学生年级仍然只能是一个值：`初一`、`初二` 或 `初三`。
- 社团至少配置一个可报名年级，可以选择多个年级。
- 现有社团的单值年级继续有效，例如 `初一` 等价于只面向初一。
- 社团年级为空的历史数据继续保留，但不能作为新的报名目标。
- 已经报名到年级为空社团的历史记录，在不更换社团时仍允许修改学生资料。
- 社团是否可报名由“学生年级是否包含在社团年级集合中”判断。
- 不修改报名名额规则、报名记录结构、报名记录 ID 或报名时间规则。

## 方案选择

采用现有 `clubs.grade` 字段保存规范化的逗号分隔年级值，不新增关联表。

示例：

```text
初一
初一,初二
初一,初二,初三
```

选择这个方案的原因：

- 不需要新增表，改动范围和部署风险较小。
- 历史单值和 `NULL` 可以直接兼容。
- 当前只有三个固定年级，集合长度可控，字符串存储足够表达完整状态。
- 通过统一解析和序列化函数避免在各路由中重复拆分字符串。

数据库中的年级顺序固定为 `初一,初二,初三` 的选项顺序，避免同一集合产生多个字符串表示。

## 数据库设计与迁移

### 初始化结构

`clubs.grade` 调整为 `VARCHAR(20) NULL`，`students.grade` 保持 `VARCHAR(10) NULL`。

不改变 `registrations` 表结构，也不改变现有唯一约束和外键。

### 已有数据库迁移

新增幂等迁移脚本：

```sql
ALTER TABLE clubs MODIFY COLUMN grade VARCHAR(20) NULL;
```

迁移不重写已有单值和空值。历史单值由应用层解析为只有一个元素的年级集合。

### 规范化规则

后端统一提供以下能力：

- 解析字符串或数组为去重后的合法年级数组。
- 按固定顺序序列化为逗号分隔字符串。
- 判断某个学生年级是否被社团年级集合允许。

非法年级、重复值和空集合在新增、编辑、导入请求中返回 HTTP 400。读取历史 `NULL` 时返回空数组，不把它误认为面向所有年级。

## API 设计

### 社团创建和编辑

新请求优先使用：

```json
{
  "grades": ["初一", "初二"]
}
```

为了兼容旧调用方，服务端继续接受单值：

```json
{
  "grade": "初一"
}
```

两种字段同时出现时使用 `grades`，并拒绝二者表达不同集合的歧义请求。

社团查询接口在保留规范化 `grade` 字符串的同时增加：

```json
{
  "grade": "初一,初二",
  "grades": ["初一", "初二"]
}
```

这样旧前端或脚本仍能读取 `grade`，新前端使用结构化的 `grades`。

### 社团导入和导出

- 导入列仍使用 `年级` 或 `grade`，值可以是单个或多个年级。
- 导入解析 ASCII 逗号、中文逗号和顿号作为分隔符，例如 `初一,初二`、`初一，初二`、`初一、初二`。
- 导出统一使用规范化的逗号字符串。
- 年级为空、含非法年级或只包含分隔符的导入行跳过，并返回明确错误。

## 报名流程

### 公共报名

`RegistrationService` 锁定社团后，使用统一年级匹配函数判断：

- 学生年级存在且在社团年级集合中：允许继续报名。
- 社团年级为空：拒绝，提示社团尚未设置可报名年级。
- 学生年级不在社团集合中：拒绝，提示社团不面向该年级。

其余名额锁定、扣减、插入报名记录和事务回滚逻辑保持不变。

### 后台修改信息

社团列表过滤改为使用多选集合判断。当前已报名社团仍然可以显示并保留，即使其年级为空；切换进入年级为空社团仍然拒绝。

更换社团时继续按照原有规则调整名额，并保留报名记录 ID 和创建时间。

## 前端设计

### 管理后台

- 新增社团和编辑社团的“可报名年级”改为多选下拉框。
- 至少选择一个年级才能保存。
- 列表中显示 `初一、初二` 形式的可读文本，空值显示“未设置”。
- 导入说明明确支持多个年级。

### 公共报名页

学生查询成功后，只显示包含学生年级的社团。

前端使用返回的 `grades` 数组；为兼容旧服务响应，如果只有 `grade` 字符串则通过同一分隔规则解析。

## 错误处理

- 创建、编辑或导入社团时未选择年级：HTTP 400。
- 年级值不在固定选项中：HTTP 400。
- 年级重复：HTTP 400。
- 社团年级为空或与学生年级不匹配：公共报名和后台换社团均拒绝。
- 任何报名保存失败继续通过现有事务回滚学生、报名和名额变化。

## 测试设计

### 年级工具测试

- 单值解析为单元素数组。
- 多值解析、去重、固定顺序序列化。
- 中文逗号和顿号导入解析。
- 非法年级、重复年级和空集合被拒绝。
- `NULL` 社团年级不匹配任何学生年级。

### 后端测试

- 社团创建、编辑和导入可以保存多个年级。
- 查询接口同时返回 `grade` 和 `grades`。
- 公共报名允许匹配集合中的任一年级，拒绝不匹配年级。
- 后台换社团和补录使用相同的多选年级规则。
- 既有单值社团行为不回归。
- 名额竞争和事务回滚行为不回归。

### 前端测试和验收

- 后台多选下拉可以加载、编辑和提交多个年级。
- 公共报名只显示匹配学生年级的社团。
- 桌面端和窄屏布局中多选标签不造成横向溢出。
- `corepack pnpm test`、`npx vue-tsc --noEmit` 和 `corepack pnpm run deploy:build` 通过。

## 不在本次范围内

- 不增加社团年级关联表。
- 不改变学生年级为多选。
- 不修改报名记录表结构和报名取消规则。
- 不处理后台真实鉴权、PM2 跨进程缓存和跨管理员版本冲突。
