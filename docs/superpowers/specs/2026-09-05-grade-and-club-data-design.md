# 年级字段与社团数据导入导出设计文档

日期：2026-09-05
状态：已确认，待用户审阅书面规格

## 背景

当前系统的社团和学生数据没有独立的年级字段，报名页也不会根据学生年级限制可报名社团。后台目前支持学生信息导入，但不支持社团数据导入和 Excel 导出。

本次增加：

1. 社团年级字段
2. 社团数据导入和 Excel 导出
3. 学生年级字段
4. 按学生年级筛选并校验可报名社团

## 已确认的需求

### 年级规则

- 年级固定选项只有：`初一`、`初二`、`初三`
- 每个社团只允许设置一个可报名年级
- 每个学生只允许设置一个年级
- 新增、编辑、导入的数据必须填写合法年级
- 历史数据允许年级为空，后台显示“未设置”

### 社团导入导出

- 只处理社团数据，不与学生或报名记录合并
- 导入支持：`.xlsx`、`.xls`、`.csv`
- 导出只支持 Excel（`.xlsx`）
- 按社团名称匹配
- 不存在则新增，已存在则更新
- 更新时保留已有报名记录
- 导入的新名额不能小于该社团已有报名人数

### 报名筛选

- 学生查询出年级后，报名页只显示相同年级的社团
- 学生年级为空时，不显示可报名社团
- 社团年级为空时，不显示在可报名列表中
- 服务端同时校验年级，不能只依赖前端筛选

## 方案选择

采用“现有 MySQL 表扩展 + 现有 Express 路由扩展”的方案。

- 与当前 MySQL、Express、Vue、Element Plus 架构一致
- 修改范围集中，不引入新的任务队列或导入批次系统
- 复用现有 `xlsx` 依赖和学生导入模式
- 年级校验放在后端，前端只负责显示和交互

## 数据库设计

### `clubs` 表

新增：

```sql
grade VARCHAR(10) NULL
```

允许为空用于兼容现有历史社团。新建或更新社团时，API 要求值必须是 `初一`、`初二` 或 `初三`。

### `students` 表

新增：

```sql
grade VARCHAR(10) NULL
```

允许为空用于兼容现有历史学生。新导入或更新学生时，API 要求值必须是 `初一`、`初二` 或 `初三`。

### 新环境初始化

更新 `server/src/storage/database/init.sql`，让新建数据库直接包含两个字段。

### 既有数据库迁移

增加独立迁移 SQL，供已部署服务器执行：

```sql
ALTER TABLE clubs ADD COLUMN grade VARCHAR(10) NULL;
ALTER TABLE students ADD COLUMN grade VARCHAR(10) NULL;
```

迁移不自动填充历史年级；历史数据保持空值，后续由管理员通过编辑或重新导入补全。

## 后端设计

### 年级校验

在社团和学生路由中使用同一组允许值：

```text
初一、初二、初三
```

非法值、空值（对新增/更新请求）返回 HTTP 400。读取接口允许返回历史空值。

### 社团接口

现有接口扩展 `grade` 字段：

- `GET /api/clubs`
  - 返回社团年级
  - 保持现有社团缓存机制，新增/编辑/导入后清除缓存
- `POST /api/clubs`
  - 接收并校验 `grade`
- `PUT /api/clubs/:id`
  - 接收并校验 `grade`

### 学生接口

- `GET /api/students`
  - 返回 `grade`
- `POST /api/students/import`
  - 导入列支持中文 `年级` 和英文 `grade`
  - 缺少年级或年级非法的行跳过并返回错误
  - 已存在学生按身份证号更新姓名、班级和年级
- `POST /api/students/lookup`
  - 返回 `name`、`className`、`grade`
- `POST /api/students/verify`
  - 返回结果增加年级信息（若存在）

### 社团导入

新增：

```text
POST /api/clubs/import
```

文件解析规则：

- 使用现有 `multer` 内存上传和 `xlsx` 解析能力
- 支持 `.xlsx`、`.xls`、`.csv`
- 表头支持中文和英文名称：
  - `社团名称` / `name`
  - `社团描述` / `description`
  - `年级` / `grade`
  - `最大报名人数` / `total_quota`
  - `社团负责人` / `manager`
  - `负责人联系方式` / `manager_contact`
- 社团名称、年级、最大报名人数为必填
- 以社团名称作为唯一匹配键
- 新社团插入时 `remaining_quota = total_quota`
- 已有社团更新时先统计报名数：
  - 新名额大于等于已报名人数：更新名额，剩余名额重新计算
  - 新名额小于已报名人数：当前行失败，不修改该社团
- 导入结果返回新增数、更新数、跳过数和最多前 10 条错误

导入结果示例结构：

```json
{
  "success": true,
  "data": {
    "createdCount": 2,
    "updatedCount": 3,
    "skipCount": 1,
    "errors": ["第 4 行：最大报名人数不能小于已报名人数"]
  }
}
```

### 社团导出

新增：

```text
GET /api/clubs/export
```

返回带中文表头的 `.xlsx` 文件，包含：

```text
社团名称、社团描述、年级、最大报名人数、剩余名额、社团负责人、负责人联系方式、创建时间、更新时间
```

`剩余名额`、时间字段仅用于导出展示，导入时不接受它们作为写入值。

现有 `GET /api/export` 报名记录 CSV 接口保持不变。

### 报名服务校验

报名路由先从数据库读取学生的真实姓名、班级和年级，再传入报名服务。报名服务读取目标社团的年级并执行：

1. 学生年级为空：返回“学生年级未设置，请联系管理员”
2. 社团年级为空：返回“该社团暂未设置可报名年级”
3. 两者不一致：返回“该社团不面向您的年级”
4. 两者一致：继续原有报名开放时间、名额、重复报名和事务处理

服务端校验必须覆盖直接调用 API 的场景。

## 前端设计

### Admin.vue：社团管理

社团列表增加“可报名年级”列，空值显示“未设置”。

新增/编辑社团表单增加固定下拉框：

```text
初一、初二、初三
```

社团管理操作区增加：

- “导入社团”按钮
- “导出 Excel”按钮

导入弹窗支持拖拽或选择 Excel/CSV，并显示新增、更新、跳过和错误信息。可提供包含必填字段的社团导入模板。

### Admin.vue：学生信息管理

学生表增加“年级”列。历史空值显示“未设置”。

更新学生导入说明和模板，要求包含：

```text
姓名、身份证号、年级、班级
```

### Register.vue：报名筛选

身份证查询成功后保存学生年级并展示年级标签。

社团列表只显示：

```ts
club.grade === student.grade
```

状态处理：

- 未查询学生信息：不显示可报名社团，并提示先查询学生
- 学生年级为空：提示联系管理员补全年级
- 没有匹配社团：提示当前年级暂无可报名社团
- 服务器返回年级校验错误：直接显示后端错误消息

## 测试计划

### 数据库与路由测试

- 社团 GET/POST/PUT 包含年级
- 社团非法年级返回 400
- 学生列表和 lookup 返回年级
- 学生导入保存年级
- 学生导入缺少年级或非法年级返回错误
- 社团导入新增和更新
- 社团导入名额小于已报名人数时跳过
- 社团导出返回合法 Excel 文件和正确表头

### 报名服务测试

- 匹配年级允许报名
- 不匹配年级拒绝报名
- 学生年级为空拒绝报名
- 社团年级为空拒绝报名
- 原有开放时间、重复报名、名额和事务测试继续通过

### 构建与手动验证

```bash
corepack pnpm test
npx tsc --noEmit
corepack pnpm run deploy:build
```

手动验证：

1. 执行数据库迁移
2. 后台新建不同年级社团
3. 导入社团 Excel 并检查新增/更新结果
4. 导出社团 Excel 并检查字段
5. 导入带年级的学生文件
6. 使用不同年级学生登录报名页，确认只能看到匹配社团
7. 直接调用 API 提交不匹配社团，确认服务端拒绝

## 不在本次范围内

- 不增加年级后台配置页面
- 不支持一个社团对应多个年级
- 不修改报名记录的数据结构
- 不把社团数据和学生/报名数据合并到同一个文件
- 不自动猜测或批量填充历史数据年级
